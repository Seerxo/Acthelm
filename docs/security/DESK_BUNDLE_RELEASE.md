# Generated Desk bundle in releases

Status: **implemented in code, not installed.** Steps marked **[FOUNDER]** need the founder: a signature, an
install or a host change.

## Rule

`app/static/*` (`desk.html`, `manifest.webmanifest`, `sw.js`, `icons/*`) is generated by `npm run build --prefix
desk`, and the build uses vite-plugin-singlefile. When a release changes `desk/` or `app/static` (measured from the
running release):

1. The reviewer gets the normal release diff (the whole tree, or `DEPLOY_PATHS` plus `desk` after a rebase). That
   diff leaves out exactly the generated files and starts with a header that names each one with its old and new
   sha256 and the `desk/` tree id. The `desk/` sources (`src`, `index.html`, `package.json`, `package-lock.json`,
   `vite.config.ts`, `public`) are part of the reviewed diff.
2. The gateway rebuilds `app/static` from `desk/` at that exact commit, offline. It runs this rebuild after its
   trusted checks and before it asks the reviewer. It then requires the rebuild to equal the payload's `app/static`:
   the same set of files and the same bytes. Otherwise the outcome is `DESK_BUILD_MISMATCH` (or `CHECKS_FAILED` when
   the build fails), the commit is final, and no review is requested.
3. The manifest carries the proof as
   `evidence.desk_build = {runner: gateway, sha, desk_tree, files: {path: sha256}, passed: true, signature}`, where
   `signature` is the gateway key's SSH signature (namespace `seerxo-desk-build`) over the canonical JSON of the
   other five fields.
4. Both verifiers (`gateway_approve` and the host's `verify_release`) verify that signature against the policy's
   `gateway_key`, then recompute `desk_tree` and every `app/static` hash from their own clone. They refuse the
   release, for **every** signer, unless the proof is gateway-signed and names this commit, this `desk/` tree and
   exactly those files and hashes. A founder signature over the manifest does not make an unsigned or forged proof
   acceptable.

A release that touches neither `desk/` nor `app/static` is unchanged: no header, no proof and the plain diff, so its
packet is byte-identical to the one the old code builds.

The packet schema and `RELEASE_REVIEW_PROMPT` are unchanged. The review-signer image (27feada), which releases do
not recreate, therefore keeps accepting packets, and `REVIEW_PROMPT_SHA256` still matches. The header lives inside
`diff`, so the fingerprint and the attestation cover it. Every other control is unchanged: risk is still classified
from the full changed paths, `app/static` is still in the payload digest and the image inputs, and a HIGH release
still needs the founder signature, the independent APPROVE, the identity checks and the ledger checks.

## Why this is at least as strong as an LLM reading the bundle

- **What is reviewed.** The minified bundle is about 1.3 MB of machine output, mostly third-party React, Radix and
  recharts code. Once it changes it no longer fits the reviewer's input (about 1,048,576 characters), and nobody can
  judge it reliably. The `desk/` sources are what a human or a model can actually read.
- **Binding.** Equality is deterministic: one changed byte in the bundle that the sources do not produce refuses the
  release. The build input contains only `desk/`, read from git objects (no `.gitattributes`, no symlinks or odd
  paths, and `app/static` starts empty), so a build cannot copy the committed bundle. Any extra file in
  `app/static` refuses the release.
- **Dependencies.** `package-lock.json` is reviewed and pins every package with an integrity hash, which `npm ci`
  verifies. The LLM could not review the dependency code inside the minified bundle either.
- **Limit (stated honestly).** The host does not rebuild, because a rebuild runs agent-written build code
  (`vite.config.ts` and npm packages), and that must never run as root on production. The rebuild result is trusted
  check evidence from the gateway, signed by the gateway key in its own namespace, so no manifest author can supply
  it. A stolen gateway key could forge it, but such a key still cannot ship a HIGH path (`app/static` is HIGH)
  without the founder's signature.

## The checks

| Where | Check |
|---|---|
| `rg.generated_facts` | `app/static` blobs at the running release and at the candidate (regular files only), and the `desk/` tree id; `required` = either differs |
| `rg.review_diff` / `review_scope` | header + `git diff` with `:(top,literal,exclude)<each generated path>`; `+ desk` after a rebase |
| `svc.default_desk_build` | exports `desk/` from git objects plus an empty `app/static`, runs `desk_build_command <dir>`, and hashes the output (regular files only) |
| `svc._tick` | no `desk_build_command` while a proof is required → `WAITING` (no attempt counted); exit 75 or a runner error → bounded retry; failed build → `CHECKS_FAILED`; unequal output → `DESK_BUILD_MISMATCH`; all of these before the review |
| `rg._check_desk_build` (called from `_check_evidence`) | for every signer: when `required`, a proof with exactly runner, sha, `passed`, `desk_tree`, `files` and `signature`; the signature verifies against the policy's `gateway_key` in `seerxo-desk-build`; the fields equal the verifier's own facts |
| `scripts/release-gateway-desk-build` | pinned `image@sha256` (root-owned pin file), `--network=none`, read-only, no capabilities, gateway uid, cache mounted read-only, `npm ci --offline --ignore-scripts`, `npm run build`; a missing prerequisite exits 75. Root never mounts, writes or reads through the caller's path: `desk/` is read as the gateway uid (`setpriv`) into a fresh root-owned staging dir (`mktemp` under root-owned `/var/lib/release-gateway-desk/stage`); symlinks, hard links and anything but regular files and directories are refused; the container has no writable host mount, builds on a 2 GiB tmpfs and emits `app/static` as a tar on stdout (capped at 64 MiB); the checked regular files are written back as the gateway uid. Unique container `--name`, `timeout -k 15 1500`, and `docker rm -f` on exit, error or signal. `seed` is refused when `SUDO_UID` or `SUDO_USER` is set. |

Tests: `tests/test_desk_bundle_release.py` (real git, the real host step, founder- and gateway-signed refusals).

## Bootstrap

Production runs the **installed** 804f2a68 verifier and gateway. What that code does (line numbers are 804f2a68):

- The gateway reviews only the tip of the policy's branch (`release_gateway_service.py:243`, `rev-parse
  refs/remotes/origin/<branch>`), and its config must name the policy's repository and branch (`:224`).
- The diff base is the running release and, with `chain_base: null`, the scope is the whole tree
  (`release_gateway.py:150` `diff_scope`; gateway `:256-259`, host `release_host.py:372,392`).
- The host accepts any commit that is an ancestor of `origin/<branch>` and descends from the running release, not
  only the tip (`release_host.py:363-368`); the branch is bound by the founder-signed policy
  (`release_gateway.py:740-743`), and the host's `fetch_url` is pinned to the GitHub remote (`release_host.py:94`).
- `install-release-bundle.py install` accepts only the SHA the ledger records as applied.

`main` (25403a1) already contains the #78 Desk, so every tip of `main` that keeps it shows the old code about 2.6M
characters of `desk.html`. The first release must therefore be a commit whose `desk/` and `app/static` are still
the caab3d3 bytes. The new rule takes effect from the second release.

No route lets the old code release a `main` tip that contains the #78 bundle, and no route needs a break-glass.
B and C avoid the public revert; B is cheaper than C. R is the only one that uses nothing but ordinary PRs.

Sudoers entry (the gateway's `TemporaryDirectory` lives in its `TMPDIR`, `/tmp` by default; adjust the prefix if
the gateway unit sets another `TMPDIR`):

    <gateway-user> ALL=(root) NOPASSWD: /usr/local/sbin/release-gateway-desk-build /tmp/gateway-desk-*

The first argument must start with `/tmp/gateway-desk-`, so `seed` cannot be the first argument. A sudoers `*` can
also match spaces, so this line alone is not a proof; the script independently refuses `seed` whenever `SUDO_UID`
or `SUDO_USER` is set, and refuses two arguments in build mode.

A later lockfile change misses the read-only cache: the build fails closed until the founder runs `seed` again.

### If a step fails

Production changes only when the host applies a signed manifest, so every failure before that leaves it as it was.

| Failure | State | Recovery |
|---|---|---|
| Old checks fail on PR-A, or the reviewer rejects it (`CHECKS_FAILED`, `REVIEW_REFUSED`, `REVIEW_UNKNOWN`) | that SHA is decided for good; `rejected_on[caab3d3]` is counted; production is caab3d3 | a new commit on `main` that answers the finding is a new SHA: it is checked and reviewed again and goes to the founder queue (it is HIGH anyway). Three infrastructure failures (`GIVEN_UP`) are recovered the same way. |
| The PR-A apply fails | the driver restores the previous images; the ledger stays `pending` | **[FOUNDER]** `reconcile` (`failed`), then a new commit |
| The bundle install fails | timers stay stopped; `current` still points at the 804f bundle unless both links were switched; production containers are untouched; the ledger bytes are checked unchanged | **[FOUNDER]** read the `BUNDLE BLOCKED` reason, fix it and run `install` again; releases stay stopped meanwhile (fail closed) |
| The new verifier misbehaves after install | nothing is applied | **[FOUNDER]** point `current` back at the retained 804f bundle directory (kept under `bundles/`). The installer has no command for this: it is a manual root step and has not been rehearsed. |
| No rebuild set-up, or its image or cache is missing | `WAITING` or bounded `RETRY_LATER`, nothing signed | **[FOUNDER]** step 5 |
| The PR-B rebuild differs (`DESK_BUILD_MISMATCH`) | decided before any review; production stays on PR-A | rebuild `app/static` in a new commit; if the difference comes from the toolchain, **[FOUNDER]** change the image pin |
| PR-B is applied and the Desk is wrong | production runs PR-B | a forward revert of `desk/` and `app/static` to PR-A's bytes: an ordinary release under the new rule (that rebuild is verified equal) |
